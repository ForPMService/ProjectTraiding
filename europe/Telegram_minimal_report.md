## Оставшийся поток

Настройки старта → заранее авторизованная пользовательская сессия → разрешение
фиксированного списка broadcast-каналов и пользователя-бота → новые Telegram
updates выбранного источника → неизменяемый `TelegramChannelPost`.

В callback нет сетевого ожидания пересылки. `Publish` помещает оригинал в один
стандартный bounded Channel и сразу вызывает `PublicationReceived(post)`.
Этот публичный выход позволяет следующему заданию подключить приём публикаций
для LLM, независимо от завершения пересылки. Обработчик выхода должен быстро
принять публикацию; асинхронные исполнители LLM и их ограничение ресурсов
появятся только в следующем задании. Сейчас подписчиков/вызовов LLM нет.

Отдельный единственный потребитель этой очереди выполняет
`ForwardMessagesAsync(..., drop_author:false)` через ту же MTProto-сессию.
Содержимое не пересказывается, Bot API не используется. Последовательность
самих пересылок не задерживает выдачу следующих принятых публикаций на выход.
Параллельное выполнение реальной LLM пока не реализовано и не проверено.

Получатель задаётся `Telegram__ForwardBotUsername`, а не токеном управляющего
бота или произвольным ControlPeerKind/Id. Сверены сигнатуры WTelegram 4.4.9:
`Contacts_ResolveUsername`, `Contacts_ResolvedPeer.peer/users`, `User.Flags.bot`,
`InputPeerUser` и `ForwardMessagesAsync`. Peer должен быть PeerUser, соответствующий
User должен иметь bot flag, полноценный access_hash и не быть min-объектом.
Это проверка кода/API, а не доказательство доступности конкретного живого бота.
Ошибка пересылки/отсутствие подтверждённого Message ID приводят к обычному
безопасному исключению фонового приложения.

Сохранена только проверка типа нового update, TL.Message, PeerChannel и
принадлежности настроенному источнику. Удалены readyAt/PublishedAt-порог,
проверки непустого/непробельного текста и дополнительный фильтр UTC Kind.
Медиа без текстового содержимого также не отсекаются этим преобразованием;
медиа не скачиваются. Время Telegram трактуется по библиотечному контракту
Unix timestamp/UTC, время приёма фиксируется в преобразовании.
Правки имеют другой тип update и не считаются новой публикацией. Дополнительная
фильтрация истории или смыслового содержимого не создавалась.

## Настройки и владение

Приём включается на старте через `Telegram__Enabled=true`. Для включённого
контура обязательны ApiId, ApiHash, PhoneNumber, абсолютные различные SessionPath
и UpdateStatePath, непустой Channels, ForwardBotUsername и положительный
ForwardQueueCapacity. OperationTimeout и ShutdownTimeout — положительные
конечные TimeSpan. Секреты задаются средой, в appsettings их нет.
При Enabled=false не создаются сетевые клиенты и не нужны реквизиты.

Channels задаётся массивом в конфигурации, для environment —
`Telegram__Channels__0`, `Telegram__Channels__1` и далее. Имена могут иметь
одно обычное начальное @, должны иметь синтаксис публичного username;
дубли регистронезависимы. Изменение списка требует нового запуска процесса.
Файла каталога/ChannelsPath, AutoStart, MaxChannels, командных timeout,
ControlPeerKind/Id, токена/владельца Bot API больше нет.

`TelegramAccountSession` владеет одним WTelegram.Client и UpdateManager.
Список каналов разрешается до подписки на updates и не меняется в рамках запуска.
Повторных запусков или второй сессии поверх активной нет. Первая интерактивная
авторизация не выполняется: отсутствие сохранённой сессии или запрос кода/пароля
останавливают инициализацию с обычным безопасным исключением.

`EuropeTelegramRuntime` владеет одной ограниченной очередью пересылки и одним
потребителем. FullMode=Wait, AllowSynchronousContinuations=false, SingleReader=true,
SingleWriter=false. TryWrite не блокирует callback. Заполненная/закрытая очередь
завершается с обычным исключением, которое наблюдает фоновый потребитель/хост;
нет Drop-режима, молчаливого успешного сброса, пользовательского статуса overflow,
новых очередей LLM, Task.Run на пост или отдельного мониторинга.

Отмена хоста закрывает допуск и writer. Принятые оригиналы дочитываются в рамках
ShutdownTimeout. Истечение срока отменяет пересылку и даёт обычную ошибку
остановки, без заявления об успешной доставке оставшегося. Сессия освобождается
в await using: client.DisposeAsync → наблюдение единственного ещё выполняемого
RPC, если WaitAsync прервался → библиотечный SaveState. Синхронный SaveState
остаётся внешним API библиотеки. Один Task запроса сохранён только для этого
обязательного наблюдения: WaitAsync не отменяет физический RPC. Массива запросов,
снимков сменяемых peers и машины состояний больше нет.

Штатный журнал WTelegram подавлен, потому что он может раскрыть данные аккаунта.
Сырые библиотечные исключения не передаются журналированию хоста; используются
обычные исключения с безопасными сообщениями. Собственных типов/категорий ошибок
и журнала публикаций нет. Доставку при аварийном завершении это задание не обещает.


NETSDK1057 — информационное сообщение о предварительной версии SDK.
Статическим чтением проверены выход публикаций, владение ресурсами, ограниченная
очередь, отсутствие удалённых функций/пакета, горячего LINQ и синхронных ожиданий.

Native AOT publish в этом задании не повторялся. Ранее выявленные ограничения
WTelegramClient остаются открыты: IL2104/IL3053, при раскрытии IL2026/IL3050
в Session/UpdateManager/Helpers и IL2067 в TL.Serialization. Они не подавлены;
PublishAot=true, IsAotCompatible=true и
JsonSerializerIsReflectionEnabledByDefault=false сохранены. Предыдущие
предупреждения Telegram.Bot относятся к удалённой зависимости и не являются
проверкой текущего проекта. Старые publish-артефакты относятся к прошлой версии.

Приложение, тесты, живой Telegram и LLM не запускались; тесты не создавались.
Не проверены в runtime: вход по сохранённой сессии, получение updates, реальная
пересылка конкретному боту, его права/Telegram-ограничения, работа выхода с
будущим LLM, заполнение очереди, остановка при незавершённых RPC, поведение
библиотек в Native AOT. Компиляция не подтверждает эти инварианты.

## Расхождения с прежними документами

План v1.3, предыдущий исполнительный промпт и старый `europe/README.md` описывают
управляющего бота, редактируемый каталог, команды, статусы и расширенную
телеметрию. Эти функции удалены по новому решению владельца. Старые документы
оставлены без изменений и являются описанием предыдущей реализации; текущий
объём описан этим отчётом. Не восстанавливались ограничения readyAt/текста,
операторское администрирование и очередь со статусами.

Правила v0.2 применены по смыслу: прежние требования подробной телеметрии и
собственной иерархии внешних ошибок уступают явному новому указанию оставить
штатные исключения/отказ хоста и удалить эту инфраструктуру. Именованные
callbacks, event и две холодные DI-лямбды — точки расширения платформы/библиотеки,
а не горячие замыкания. ValueTask без token у DisposeAsync — контракт IAsyncDisposable.
Поведенческие гарантии запуском не подтверждены.

`backend/`, `.gitignore`, `europe/global.json`, `.editorconfig` и старый README
не менялись. Исходное пользовательское удаление
`Задание_Telegram_приёмник_усиленное_v2.md` и неотслеживаемый файл правил в docs
оставлены без изменения и не включены в коммит. Развёртывание, push и следующий
этап LLM не выполнялись.
