# Правила интерфейса и дизайн-система оператора

Версия 0.1. Документ описывает визуальный язык, правила и ограничения пульта оператора.

---

## Как читать этот документ

Документ описывает целевые правила интерфейса. Он не описывает текущее состояние макетов и не перечисляет, что уже нарисовано.

Каждое правило дано вместе с причиной. Правило без причины превращается в вкусовщину: его обходят или соблюдают механически. Правило, у которого понятна причина, применяется по существу.

Утверждения делятся на три вида. **Инвариант** — не пересматривается. **Принцип** — правило формы, верное при любой реализации. **Гипотеза** — текущее предположение, которое может измениться.

Визуальный baseline интерфейса — Dashboard v7. Принципы этого документа извлечены из Dashboard v7 и проверены на нём. Если правило и макет расходятся — правило является источником истины, макет подлежит исправлению.

## 1. Назначение интерфейса

Пульт оператора — единственный UI платформы в первой очереди. Это рабочий инструмент одного человека, который управляет сбором данных Московской биржи, проверяет качество и готовит инфраструктуру для будущей торговли. *(инвариант)*

Это не торговый терминал. Не Bloomberg. Не серая CRUD-админка. Не временная developer-панель. Это продуктовый пульт оператора рыночных данных. *(инвариант)*

**Причина.** Оператор работает с пультом каждый день. Если интерфейс ощущается как временная поделка — он перестаёт доверять данным, которые в нём видит. Продуктовое качество — не эстетика ради эстетики, а условие доверия.

## 2. Принципы

Шесть сквозных ценностей, которым подчинены все правила ниже.

### Быстрое считывание

Оператор проводит на экране 10–30 секунд за визит. Каждый экран должен отвечать на один главный вопрос без скролла и без клика. *(принцип)*

**Причина.** Пульт — не приложение, в котором сидят часами. Оператор зашёл, считал статус, увидел проблему, ушёл в детали. Если для ответа на вопрос «всё ли в порядке» нужно скроллить или кликать — экран не работает.

Dashboard отвечает: «что происходит с системой». Загрузки отвечают: «что я сейчас делаю». Инструменты отвечают: «чем я управляю». Один экран — один вопрос.

### Плотность без шума

На экране много данных, но нет визуального мусора. Не Bloomberg (20 панелей, всё кричит), не Apple (пустота, три слова на странице). Золотая середина: таблица на 15 строк читается, метрики считываются, статусы различимы. *(принцип)*

**Причина.** Оператор управляет сотнями инструментов, десятками заданий и несколькими типами данных. Это плотный домен. Попытка упростить его до «3 карточки и кнопка» скрывает реальность. Попытка показать всё сразу без иерархии — перегружает. Правильная плотность — это когда каждый пиксель несёт информацию, но глаз не теряется.

### Цвет только со смыслом

Если элемент цветной — он либо действие (indigo), либо состояние (status palette). Декоративного цвета нет. Нет цветных фонов «для красоты», нет gradient-баннеров, нет accent-подсветки без функции. *(инвариант)*

**Причина.** На экране, где зелёный = «задание прошло», а красный = «задание упало», любой посторонний цвет забирает ресурс внимания. Если синяя кнопка и голубой running-бейдж стоят рядом — глаз спотыкается. Когда цвет используется только со смыслом, каждое цветное пятно на экране — это сигнал.

### Действие очевидно

В каждой строке таблицы, в каждом alert, на каждом пустом экране оператор видит, что делать дальше. Нет экранов без следующего шага. *(принцип)*

**Причина.** Пульт — рабочий инструмент, не отчёт. Отчёт показывает «было 3 ошибки». Инструмент показывает «было 3 ошибки — вот кнопка Повторить». Каждая единица информации сопровождается действием — это то, что отличает пульт от Grafana-дашборда.

### Продуктовое качество

Интерфейс должен ощущаться как продукт, а не как временная dev-панель. Hairline-бордеры вместо толстых рамок. Двухслойные тени вместо bootstrap-теней. Display-числа вместо мелкого текста. Русские статусы вместо английских. *(принцип)*

**Причина.** Человек, который поднял систему через docker-compose и открыл пульт впервые, должен понять за 5 секунд: это серьёзный инструмент, которому можно доверять. Визуальное качество — proxy доверия. Если интерфейс выглядит как поделка — оператор будет перепроверять его данные через CLI, и пульт станет бесполезным.

### Простота системы

Два шрифта, одна accent-палитра, одна status-палитра, одна spacing-шкала. Каждое добавление — нового цвета, шрифта, анимации, варианта компонента — должно быть оправдано так же строго, как новая абстракция в серверном коде (правило обёртки: три причины). *(принцип)*

**Причина.** Дизайн-система с 8 accent-цветами и 4 шрифтами не масштабируется. На втором экране начинаются расхождения, на пятом — хаос. Простая система (один accent, шесть статусов, два шрифта) выдерживает 10 экранов без деградации — каждый новый экран собирается из тех же деталей.

## 3. Визуальный язык: Slate + Indigo

Базовый визуальный язык — Slate + Indigo. Тёмная тема основная. *(принцип)*

**Причина.** Проверено на плотном Dashboard с 15 строками, 4 метриками и 4 alerts. Slate-база (#0B0D10) мягче чистого чёрного — не утомляет за 6+ часов работы. Indigo (#6366F1) отделён от всех статусных цветов — не конфликтует ни с зелёным, ни с жёлтым, ни с красным.

**Отклонённые альтернативы:**
- Onyx + Champagne — champagne конфликтует с warning-жёлтым; на плотном экране даёт ощущение «жёлто-коричневое всё». Отклонён после Dashboard-теста. Возврат только через новый тест на реальном экране.
- Pure Mono + Teal — резерв. Чистый чёрный утомляет при долгой работе. Не развиваем, пока Slate + Indigo не провалится на 10 экранах.
- Красный/коралловый accent — конфликтует с error. Отклонён на v4.

**Светлая тема** — provisional. Токены ниже содержат light-значения, но тема не проходила экранный тест. Перед production-использованием требуется проверка на Dashboard и Loads. *(гипотеза)*

## 4. Главное правило цвета: accent ≠ статус

Indigo означает действие. Статусный цвет означает состояние данных. Они никогда не пересекаются. *(инвариант)*

**Причина.** Когда один цвет означает и «нажми» и «ошибка» (как в Jira и Bitrix), оператор перестаёт различать интерактивность и состояние. На пульте, где ошибка означает потерянные данные, это опасно.

**Где используется accent (indigo):** primary кнопка, active nav item (2px left bar + текст), action-ссылки в таблице и alerts, selected row border, focus ring, toggle on (приглушённый).

**Где используется accent НЕ допускается:** индикаторы статуса, бейджи done/error/warning/running, фон строк с ошибкой, цвет warning-текста.

## 7. Пространство

Шкала кратная 4px. *(принцип)*

**Причина.** Единая шкала не даёт появиться «случайным 13px» и «произвольным 22px». Всё выровнено по сетке, даже если сетка невидима.

| Токен | Значение | Типичное применение |
|-------|----------|---------------------|
| space.1 | 4px | Micro-gap (между точкой и текстом в бейдже) |
| space.2 | 8px | Gap между бейджами |
| space.3 | 12px | Gap внутри nav item, inner gap строки |
| space.4 | 16px | Padding sidebar, gap между metric cards |
| space.5 | 20px | Padding карточек (metric) |
| space.6 | 24px | Padding hero, row horizontal, gap секций sidebar |
| space.7 | 28px | Gap между блоками контента |
| space.8 | 32px | Main content padding |
| space.9 | 36px | Hero card inner padding |
| space.10 | 40px | Main content bottom padding |

Значения, не укладывающиеся в шкалу (10px, 14px, 18px, 22px), фиксируются как component-specific. Это допустимо для кнопок, карточки аккаунта и gaps внутри метрик — там стандартные значения дают или слишком тесно, или слишком просторно.

## 8. Тени и глубина

Двухслойная система: длинная мягкая тень + короткая резкая. На каждой карточке — 1px inner highlight белым 3–4% сверху (имитация света на верхней грани). *(принцип)*

**Причина.** Однослойная тень (0 2px 4px) — это Bootstrap. Двухслойная + highlight — это материальность, как у Linear/Stripe. Без highlight карточки лежат плоско; с ним — ощущается глубина.

| Токен | Значение | Где |
|-------|----------|-----|
| shadow.card | 0 6px 16px -3px rgba(0,0,0,0.40), inset 0 1px 0 rgba(255,255,255,0.035) | MetricCard, table card, alert row |
| shadow.hero | 0 16px 40px -8px rgba(0,0,0,0.50), 0 2px 4px rgba(0,0,0,0.35), inset 0 1px 0 rgba(255,255,255,0.04) | Hero status card |
| shadow.button-primary | 0 4px 12px -2px rgba(99,102,241,0.30), inset 0 1px 0 rgba(255,255,255,0.18) | Primary button — indigo glow + top highlight |
| shadow.dropdown | 0 12px 32px -4px rgba(0,0,0,0.60), 0 2px 6px rgba(0,0,0,0.40) | Dropdown, popover |
| shadow.modal | 0 24px 64px -12px rgba(0,0,0,0.70), 0 8px 16px -4px rgba(0,0,0,0.50) | Modal, drawer |

Light theme: drop shadow opacity ×0.3, inner highlight не нужен.

## 9. Правила таблиц

Таблица — основной рабочий объект операторских экранов. *(принцип)*

**Причина.** Оператор управляет инструментами, заданиями и диапазонами. Все они — списки с атрибутами. Если таблица плохо читается — пульт не работает.

**Правила:**

- Header: фон bg.app (утапливается), текст 9px uppercase tracked, color text.muted. *(принцип)*
- Разделители: 1px border.hairline с opacity 0.6 — на границе видимости. *(принцип)*
- Числа: моноширинные, font-weight 500, right-aligned. *(принцип)*
- Тикер: body-bold (SBER), под ним mono-small тип данных (candles). *(принцип)*
- Hover: bg.row-hover + 1px muted left marker. Тихий — не кричит. *(принцип)*
- Selected: bg.row-selected (rgba 6%) + 2px accent left bar. *(принцип)*
- Row padding: 16px vertical, 24px horizontal.
- Table card: bg.surface, border.subtle, radius.card, shadow.card, overflow hidden.
- Table caption стоит НАД table card: section label + count + StatusFilterChips + LastUpdatedLabel.

## 10. Правила действий в таблице

Каждая строка имеет контекстное действие. Текст и цвет зависят от статуса строки. *(принцип)*

**Причина.** Фиксированное «Открыть» на всех строках превращает таблицу в отчёт. Контекстное действие превращает таблицу в рабочий инструмент: оператор видит не просто «строка», а «строка, которую надо повторить».

| Статус | Текст | Цвет | Действие |
|--------|-------|------|----------|
| успешно | Открыть | accent | navigate → детали |
| выполняется | Детали | accent | navigate → прогресс |
| ожидает | Детали | accent | navigate → параметры в очереди |
| ошибка | Повторить | status.error.fg | retry job |
| внимание | Проверить | status.warning.fg | navigate → диагностика |

## 11. Иерархия действий

На экране может быть только одно главное действие. *(принцип)*

Primary button используется для основного действия страницы: «Создать задание». Вторичные действия используют secondary button или accent-ссылку. Если на странице два важных действия — одно главное (primary), второе вторичное (secondary). Например: «Создать задание» — primary, «Массовая загрузка» — secondary.

**Причина.** Две primary-кнопки создают ложный выбор и ломают визуальную иерархию. Оператор должен сразу видеть основной следующий шаг — один, не два.

Primary action не дублируется на экране. Если «Создать задание» стоит в hero-области — в footer его не повторяем. *(принцип)*

## 12. Состояния страницы

Каждая рабочая страница описывается минимум в пяти состояниях. *(принцип)*

| Состояние | Что видит оператор |
|-----------|-------------------|
| loading | Скелетные заглушки на месте данных. Не спиннер, не пустой экран |
| empty | Данных ещё нет. Направление к действию: «Создайте первое задание» + кнопка |
| empty-filtered | Данные есть, но фильтр ничего не нашёл. «Нет заданий по этим фильтрам» + ссылка «Сбросить» |
| populated | Данные есть. Нормальная работа |
| error | Страница не получила данные. Описание проблемы + кнопка «Повторить» |

Empty и error не смешиваются. Empty направляет к действию. Error объясняет проблему и даёт действие восстановления. *(принцип)*

**Причина.** Страница без явного описания состояний получит «белый экран» на empty и «крутилка навсегда» на loading. Это ломает доверие оператора. Пять состояний — минимум, который гарантирует, что оператор всегда видит осмысленный экран.

## 13. Правила alerts

Alerts разделены по severity: КРИТИЧНО (error) и ВНИМАНИЕ (warning + info). *(принцип)*

**Причина.** Плоский список «4 предупреждения» не даёт оператору приоритет. Split на КРИТИЧНО/ВНИМАНИЕ сразу показывает: красное — действуй сейчас, жёлтое — посмотри когда сможешь.

**Структура alert:**
- Вертикальный бар 3px × stretch слева (цвет = fg статуса). Не точка — бар визуально сильнее и сканируется быстрее.
- Title: body-medium, text.primary.
- Sub-line: caption, text.secondary (не muted — это ключевой контекст: HTTP-код, дата, причина).
- Action справа: body-bold. Цвет зависит от типа действия:
  - Навигация (Открыть карточку, Ввести тариф) → accent.
  - Retry (Повторить) → status.error.fg.
  - Reload (Перезагрузить) → status.warning.fg.

## 14. Правила форм и overlay

### Modal

- Появляется по центру экрана, затемнение фона.
- Escape закрывает, если в форме нет несохранённых изменений.
- Клик по затемнению не закрывает модалку с формой. Для простых информационных модалок без ввода данных — закрытие по клику на затемнение допустимо.
- Focus trap: Tab не уходит за пределы модалки.
- Transition: motion.slow (300ms), ease.enter.

### Drawer

- Slide-in справа, поверх content area.
- НЕ перекрывает sidebar и topbar.
- Escape закрывает. Клик вне drawer НЕ закрывает (чтобы не потерять контекст на рабочем пульте). *(принцип)*
- Повторный клик по той же строке — закрывает. Клик по другой — переключает.
- Width: 480px. Shadow: shadow.modal. Radius: radius.panel (left corners).

### Empty state

- Пустое состояние — не ошибка, а направление к действию. *(принцип)*
- Icon: 48px, text.disabled. Heading: body-bold, text.secondary. Description: body, text.secondary (не muted). Action: Button.primary или accent-ссылка.

**Причина.** Пустой экран говорит «сломано». Пустой экран с кнопкой говорит «вот что дальше». Для оператора, который только поднял систему, разница между ними — это разница между паникой и следующим шагом.

## 15. Правила статусных бейджей

StatusBadge: dot 5px + text 11px/500 на soft-фоне с border. *(принцип)*

| Вариант | fg | soft | border | Текст |
|---------|----|----|--------|-------|
| success | status.success.fg | status.success.soft | status.success.border | успешно |
| warning | status.warning.fg | status.warning.soft | status.warning.border | внимание |
| error | status.error.fg | status.error.soft | status.error.border | ошибка |
| running | status.running.fg | status.running.soft | status.running.border | выполняется |
| pending | status.pending.fg | status.pending.soft | status.pending.border | ожидает |
| neutral | status.neutral.fg | status.neutral.soft | status.neutral.border | — |

Padding: 3px 9px 3px 7px. Radius: 4px. Dot gap: 6px. Текст badge — всегда русский. *(принцип)*

**Причина.** Оператор работает на русском. Done/running/error в английском — это язык разработчика, не пользователя. Маппинг backend status → русский label живёт в одном месте.

---

## 16. Правила StatusFilterChips

Active-состояние chip показывает выбор через accent (bg accent.subtle, border accent.default). Статусный цвет используется только для точки/счётчика внутри chip, не для заливки всего chip. *(принцип)*

**Причина.** Принцип accent ≠ статус. Если active chip «Ошибка» красный, а primary button «Создать задание» индиго — оператор считывает два конкурирующих визуальных центра. Accent на chip показывает «это ты выбрал», точка внутри показывает «это про ошибки».

---

## 17. Правила текстов

Статусы на русском: успешно, выполняется, ожидает, внимание, ошибка. *(принцип)*

Автообновление, не polling. Пишем «автообновление каждые 5 сек», не «polling every 5 seconds». В технических backend-документах термин polling допустим. В UI — русский. *(принцип)*

Pending — это «ожидает», не «disabled» и не «пусто». Pending визуально отличается от neutral. *(принцип)*

**Причина.** Задание в очереди — нормальное рабочее состояние. Disabled — неактивный элемент. Если они выглядят одинаково, оператор не видит очередь.

## 18. Что запрещено

- Glassmorphism (backdrop-filter: blur) на основных панелях.
- Neon glow, casino gold (#FFD700), crypto-neon.
- Bloomberg-overload (20 панелей на экране).
- Gradient overlay на весь экран.
- Decorative patterns, textures, background images.
- Serif шрифты (кроме, возможно, logo — гипотеза).
- Hover glow на кнопках и строках.
- Дублирование primary action (кнопка «Создать задание» в hero И в footer одновременно).
- Английские статусы в UI (done, running, error — только в коде).
- Использование accent-цвета для индикации статуса.
- Использование статусного цвета для primary кнопки.

## 19. Motion

| Токен | Значение | Где |
|-------|----------|-----|
| motion.fast | 100ms | Button press, toggle switch, badge appear |
| motion.normal | 200ms | Sidebar hover, row hover, tooltip |
| motion.slow | 300ms | Modal/drawer open, section expand |
| ease.standard | cubic-bezier(0.4, 0, 0.2, 1) | Большинство переходов |
| ease.enter | cubic-bezier(0, 0, 0.2, 1) | Элемент появляется |
| ease.exit | cubic-bezier(0.4, 0, 1, 1) | Элемент уходит |

**Принцип:** action-feedback (кнопка нажалась, toggle переключился) — fast. Декоративные переходы (drawer, modal) — slow. Оператор не должен ждать feedback, но должен видеть куда ушёл фокус.

## 21. Автообновление

UI показывает состояние автообновления: когда данные обновлены, когда обновление идёт, когда данные устарели и когда обновление сломалось. *(принцип)*

Технический способ обновления не является частью дизайн-системы. На текущем этапе используется периодический HTTP-запрос каждые 5 секунд. Это гипотеза реализации для первой версии пульта. *(гипотеза)*

При ошибке обновления старые данные не скрываются. Экран показывает состояние устаревших данных: время последнего успешного обновления и явный индикатор ошибки. *(принцип)*

**Причина.** Скрывать данные при потере обновления хуже, чем показывать устаревшие. Оператор видит «данные за 2 минуты назад» и принимает решение. Пустой экран с ошибкой отнимает у него даже это.

После 3 неудачных попыток обновления: LIVE-индикатор → update-error (красный), LastUpdatedLabel → «ошибка обновления · последние данные N мин назад».

## 23. Definition of Done для UI-экрана

Экран считается принятым, если:

1. Не похож на Jira / Bitrix / Bootstrap admin.
2. Таблица читается на 15+ строках с 4+ статусами одновременно.
3. Accent (indigo) используется только для действий, нигде не индицирует статус.
4. Статусы различимы рядом друг с другом (success + warning + error в соседних строках).
5. Empty state направляет к действию, не пугает.
6. Все статусы на русском.
7. Hover не кричит. Selected не заливает строку.
8. Display-числа в метриках — визуальные герои.
9. Tени двухслойные + inner highlight.
10. Primary action не дублируется на экране.

## 24. Сводка правил

| Правило | Суть | Причина |
|---------|------|---------|
| Slate + Indigo | Тёмная тема, slate-база, indigo-accent | Проверено на плотном Dashboard, не утомляет |
| Accent ≠ статус | Indigo = действие, цвет = состояние | Иначе оператор не различает кнопку и ошибку |
| Два шрифта | Inter + JetBrains Mono | Каждый лишний шрифт — шум |
| Display-числа | 44px mono — герой карточки | Число важнее label |
| Двухслойные тени | Длинная + короткая + inner highlight | Bootstrap-тень = плоско; двухслойная = материальность |
| Hairline borders | 1px на грани видимости | Толстая рамка = админка |
| Тихий hover | bg + 1px muted left | Hover не должен соревноваться с selected |
| Alerts по severity | КРИТИЧНО / ВНИМАНИЕ | Плоский список не даёт приоритет |
| Контекстные actions | Текст и цвет по статусу строки | Фиксированное «Открыть» = отчёт, контекстное = инструмент |
| Русские статусы | успешно / выполняется / ожидает / внимание / ошибка | UI на русском, код на английском |
| Pending ≠ disabled | Slate-серый, не neutral-серый | Очередь — рабочее состояние, disabled — неактивный элемент |
| Muted ≠ secondary | Muted только для плейсхолдеров | Sub-line в alert — ключевой контекст, не метаданные |
| Empty state = направление | Говорит «что делать», не «нет данных» | Пустой экран без действия = паника |
| Drawer не перекрывает sidebar | Escape закрывает, click outside — нет | На рабочем пульте случайное закрытие = потеря контекста |
| Автообновление | UI показывает актуальность данных и состояние устаревших данных | Скрывать устаревшие данные хуже, чем честно показать время последнего обновления |
