# Карта экранов фронтенда — блок C

**Назначение.** Это документ-ориентир на весь блок C (Angular-консоль). Он сопоставляет
каждую страницу макета с тем, что реально отдаёт сервер сегодня, и помечает, что строим
сейчас, а что остаётся прочерком до блока D (рыночные данные). Карта опирается на
подтверждённый контракт сервера (контуры `Vitrine` и `Management`), сверенный с
репозиторием.

**Как читать.** Для каждой страницы указано: маршрут фронта, адрес сервера, поля с реальным
источником, и блоки-прочерки (видение блока D). Прочерк означает «нарисовано в макете, но
источника пока нет» — такие блоки в первой очереди не строим, добавим в блоке D, когда у
них появятся данные.

**Базовый адрес сервера в разработке:** `http://localhost:5025`. Фронт достукивается до него
через посредник разработки (прокси на пути `/vitrine`, `/management`, `/operations`).

## Сводная таблица действующих адресов сервера

| Адрес сервера | Метод | Что отдаёт | Страница-потребитель |
|---|---|---|---|
| `/vitrine/instruments` | GET | список инструментов | Каталог |
| `/vitrine/cards/stock/{secid}` | GET | карточка акции (404 если нет) | Карточка акции |
| `/vitrine/cards/futures/{secid}` | GET | карточка фьючерса (404 если нет) | Карточка фьючерса |
| `/vitrine/relations/{secid}` | GET | связи по коду инструмента | Блок «Связи» в карточке |
| `/vitrine/relations` | GET | все связи (общий список) | — (отдельного экрана не делаем) |
| `/vitrine/calendar` | GET | особые дни торгов | Календарь |
| `/vitrine/tariffs` | GET | список тарифов | Издержки |
| `/vitrine/status` | GET | счётчики сводки | Dashboard |
| `/management/tariffs` | POST | создать тариф (400 текст при ошибке) | Форма тарифа |
| `/management/relations` | POST | создать связь (400 текст при ошибке) | Форма связи |
| `/operations/moex/sync/bootstrap` | GET | первичная загрузка справочника | Кнопка в пустых состояниях |

## Страница 1 — Каталог инструментов

- **Маршрут фронта:** `/instruments`
- **Адрес сервера:** `GET /vitrine/instruments`
- **Приоритет:** первый тонкий срез (с него начинаем)

**Реализуем сейчас (есть источник):**
- Колонка «Инструмент»: код + название (`Secid`, `Shortname`, `Secname`)
- Колонка «Тип»: акция / фьючерс (`InstrumentType`)
- Колонка «Базовый актив»: только у фьючерсов (`AssetCode`), у акций пусто
- Колонка «Действие»: ссылка «Открыть» (переход к карточке)
- Вкладки «Все / Акции / Фьючерсы» — фильтр на стороне фронта
- Поиск — фильтр на стороне фронта
- Счётчики «Акции N / Фьючерсы N» — подсчёт на стороне фронта
- Пустое состояние: каталог вернул пустой список → кнопка «Загрузить справочник»

**Прочерк (видение блока D):**
- Колонки: статус данных, что загружено, период, покрытие, обновлено, флаги
- Переключатель «отслеж.»
- Действия «Загрузить / Дозагрузить / Проверить»

## Страница 2 — Карточка акции

- **Маршрут фронта:** `/instruments/stock/:secid`
- **Адреса сервера:** `GET /vitrine/cards/stock/{secid}` (404 если нет) + `GET /vitrine/relations/{secid}`

**Реализуем сейчас:**
- Шапка: код, название, «акция · режим торгов» (`Boardid`)
- Блок «Параметры»: режим (`Boardid`), листинг (`ListLevel`), лот (`Lotsize`),
  шаг цены (`Minstep`), валюта (`CurrencyId`), ISIN (`Isin`), статус торгов (`Status`)
- Блок «Связи»: связанный инструмент / базовый актив, тип связи, достоверность
  (`RelationType`, `TargetSecid`/`TargetAssetCode`, `Confidence`)
- Ссылка «Создать ручную связь» → форма связи

**Прочерк (видение блока D):**
- «Номинал» (поля `facevalue` нет в схеме V017)
- Заголовочные метрики: покрытие, загружено типов, последнее обновление, дней без обновления
- Таблица «Покрытие данных», блок «Пропуски»
- «Ограничения и изменения» (приостановки, история атрибутов)
- Журнал «Последние действия», переключатель «Отслеживание»
- Кнопки «Создать задание», «Обогатить карточку»

## Страница 3 — Карточка фьючерса

- **Маршрут фронта:** `/instruments/futures/:secid`
- **Адреса сервера:** `GET /vitrine/cards/futures/{secid}` (404 если нет) + `GET /vitrine/relations/{secid}`

**Реализуем сейчас:**
- Шапка: код, «Фьючерс · базовый актив · режим», поле «До экспирации»
  (вычисляется из даты экспирации)
- Блок «Параметры»: базовый актив (`AssetCode`), режим (`Boardid`),
  экспирация (`LastTradeDate`), дата поставки (`LastDelDate`),
  гарантийное обеспечение (`InitialMargin`), объём лота (`Lotvolume`),
  шаг цены (`Minstep`), цена шага (`Stepprice`),
  верхний/нижний лимиты (`HighLimit`, `LowLimit`), комиссия биржи (`BuysellFee`)
- Блок «Связи»: как у акции
- Ссылка «Создать ручную связь»

**Прочерк (видение блока D):**
- «Открытый интерес», «Скальперская комиссия» (полей нет в схеме)
- «Загружено типов», таблица «Покрытие данных»
- Таблица «Контракты Si» (соседние контракты)
- Журнал «Последние действия»

## Страница 4 — Dashboard (сводка)

- **Маршрут фронта:** `/dashboard` (стартовый)
- **Адрес сервера:** `GET /vitrine/status` (+ `GET /vitrine/calendar` для плашки готовности календаря)

**Реализуем сейчас:**
- Строка состояния: «Система настроена / не настроена»
- Признак сегодняшнего торгового дня (`StockTradingToday`, `FuturesTradingToday`)
- Плашки готовности: «Инструменты» (каталог непуст), «Календарь» (`calendar` непуст),
  «Тарифы» (`TariffsCount` > 0)
- Плитка «Всего инструментов» с разбивкой акции/фьючерсы
  (`InstrumentsTotal`, `InstrumentsStock`, `InstrumentsFutures`)
- Пустое состояние: «Система не настроена» + кнопка «Загрузить инструменты»

**Прочерк (видение блока D):**
- Метрики «Карточки обогащены», «Задания сегодня», «Строки за 24 ч», «Готовность %»
- Блоки «Критично», «Внимание»
- Таблица «Последние загрузки», индикатор LIVE с автообновлением
- Плашки готовности «Обогащение», «Ограничения», «APIM key»

## Страница 5 — Календарь

- **Маршрут фронта:** `/calendar`
- **Адрес сервера:** `GET /vitrine/calendar`

**Реализуем сейчас:**
- Таблица: дата, рынок, торгуется ли (зелёная/серая плашка),
  дата сессии (может быть пустой), причина (H — праздник, W — выходной с сессией)
- Переключатель рынка stock / futures (фильтр на фронте)
- Пустое состояние: «Календарь не загружен» + ссылка «Загрузить справочник»

**Примечание:** отдельного экрана календаря в исходном макете нет — раскладка простая,
строим по образцу таблицы.

## Страница 6 — Издержки (тарифы)

- **Маршрут фронта:** `/costs`
- **Адреса сервера:** `GET /vitrine/tariffs` (список) + `POST /management/tariffs` (создание)

**Реализуем сейчас:**
- Таблица тарифов: брокер, название, рынок, тип комиссии, значение, валюта,
  мин. комиссия, порог оборота, действует с, действует по, комментарий
  (незаданные необязательные поля — «—»)
- Кнопка «Добавить тариф» → форма
- Форма «Новый тариф» (правая панель): поля `BrokerName`, `TariffName`, `Market`,
  `FeeType`, `FeeValue`, `FeeCurrency` (пусто → RUB на стороне базы),
  `MinFee`, `TurnoverThreshold`, `ValidFrom` (ГГГГ-ММ-ДД), `ValidTill`, `Comment`
- Ошибка валидации с сервера: 400 с текстом — показать дословно
- Пустое состояние: «Тарифы не заданы» + кнопка «Добавить тариф»

## Форма — Создать ручную связь

- **Открывается из:** карточки инструмента (ссылка «Создать ручную связь»)
- **Адрес сервера:** `POST /management/relations`

**Реализуем сейчас:**
- Исходный инструмент — закреплён (код текущей карточки), не редактируется
- Целевой инструмент (`TargetSecid`) или целевой базовый актив (`TargetAssetCode`) —
  нужен хотя бы один из двух
- Тип связи (`RelationType`): future_underlying / same_underlying / manual_related
- Достоверность (`Confidence`): auto / manual (по умолчанию manual)
- Комментарий (`Comment`)
- Ошибка валидации с сервера: 400 с текстом — показать дословно

---

## Синхронизация — первичная загрузка справочника

- **Адрес сервера:** `GET /operations/moex/sync/bootstrap`
- **Точки входа:** кнопка «Загрузить справочник» в пустом каталоге и пустом дашборде
- **Поведение:** строго явный запрос по кнопке (без планировщика), ответ с запретом
  кэширования; после успеха фронт перечитывает каталог
- Возвращает массив `LoadResultDto` (поля: операция, источник, цель, статус,
  число на входе, записано строк, время)

## Видение блока D (на фронте сейчас НЕ строим)

Эти страницы есть в полном видении (макет, спецификация), но сервера под них пока нет.
Рисуем их позже как опережающий дизайн или реализуем, когда появится рыночная загрузка.

- **Загрузки** — задания и диапазоны загрузки рыночных данных
- **Качество** — проверки качества загруженных данных
- **Рейтинг** — сводный рейтинг инструментов по покрытию
- **Операции** — страница синхронизации с автозаданиями
- **Настройки** — ключ APIM, raw capture, лимитер, подключения
- **Форма «Создать задание»** и **«Массовая загрузка»** — создание заданий загрузки

## Порядок реализации (тонкие срезы)

1. **Каталог** на `GET /vitrine/instruments` — первый зелёный прогон с реальными данными
2. **Карточки** (акция, фьючерс) + блок «Связи»
3. **Форма связи** (`POST /management/relations`)
4. **Издержки**: список + форма тарифа (`GET/POST tariffs`)
5. **Календарь** (`GET /vitrine/calendar`)
6. **Dashboard** (`GET /vitrine/status`) + кнопка первичной загрузки
7. Позже — **видение блока D**, когда заработает рыночная загрузка

Каждый срез — один логический шаг, между шагами проверка сборки и зелёный прогон.
