### Задача 2: создать OpenTelemetryExtensions.cs
**Файл:** `src/Platform/PM.Platform.Infrastructure/Observability/OpenTelemetryExtensions.cs`  
**Папку Observability создать самому**

**Что должен делать метод `AddPlatformTelemetry()`:**
- читает `OTEL_SERVICE_NAME` из переменных окружения
- читает `OTEL_EXPORTER_OTLP_ENDPOINT` из переменных окружения
- если endpoint НЕ задан — ничего не делает (сервис просто работает без OTel)
- если задан — включает трейсы, метрики, логи через OTLP
- трейсы: HTTP входящие + HTTP исходящие, но НЕ `/health` и `/metrics`
- метрики: HTTP + runtime (.NET GC, память, потоки)
- логи: structured logging через OTel (IncludeScopes, IncludeFormattedMessage)

---

### Задача 3: создать PlatformHealthChecksExtensions.cs
**Файл:** `src/Platform/PM.Platform.Infrastructure/HealthChecks/PlatformHealthChecksExtensions.cs`  
**Папку HealthChecks создать самому**

**Что написать:** три метода-расширения на `IHealthChecksBuilder`

| Метод | Что делает | Тег |
|-------|-----------|-----|
| `AddRedisHealthCheck(connectionString)` | PING к Redis | `"ready"` |
| `AddPostgresHealthCheck(connectionString)` | SELECT 1 к Postgres | `"ready"` |
| `AddUrlHealthCheck(url, name)` | GET запрос к URL | `"ready"` |

**Тег `"ready"` обязателен** — по нему `/health/ready` знает какие проверки запускать.

---

### Задача 4: переписать IAM Api Program.cs
**Файл:** `src/IAM/PM.IAM.Api/Program.cs`

**Порядок регистрации:**
1. `ForwardedHeaders` — чтобы сервис знал реальный IP/host за nginx
2. `builder.AddPlatformTelemetry()` — из задачи 2
3. `builder.Services.AddHealthChecks()` с двумя проверками:
   - Postgres (строка из `ConnectionStrings:IamDb` в конфиге)
   - Redis (из `Redis:Host`, `Redis:Port`, `Redis:Password` в конфиге)
4. Два endpoint'а:
   - `GET /health` — liveness, всегда 200, зависимости не проверяет
   - `GET /health/ready` — readiness, 503 если Postgres или Redis недоступны
5. Ответ в JSON: `{ status, checks: { name: { status, duration } } }`
