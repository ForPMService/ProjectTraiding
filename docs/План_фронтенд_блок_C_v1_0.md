# План фронтенд-проекта — блок C (Angular-консоль)

**Назначение.** Маршрут разработки фронтенда: что строим, в каком порядке, по каким
принципам, и как при этом учиться. Документ опирается на дизайн-систему
(ui_design_system_v0_1), спецификацию страниц (ui_pages_spec_v0_1), карту экранов
(Карта_экранов_блок_C) и подтверждённый контракт сервера.

---

## 1. Что уже сделано

- Окружение готово: Node.js v26, npm 11, Angular CLI 22.
- Проект создан: `frontend/` в корне монорепозитория, рядом с `backend/`.
  Флаги: `--style=scss --routing --ssr=false --package-manager=npm`.
- Первый зелёный прогон пройден: `ng serve` поднимает приложение на `localhost:4200`.
- Устройство Angular разобрано: цепочка запуска, анатомия компонента,
  маршруты, сигналы.
- Тема собрана: `theme_tokens_v1_0.scss` — переменные CSS из дизайн-системы.
- Карта экранов собрана и сверена с репозиторием.

---

## 2. Архитектурные решения (зафиксированы)

- **Стек:** Angular 22, отдельностоящие компоненты (standalone), сигналы, SCSS.
- **Тема на переменных CSS** (`var(--...)`), не на переменных SCSS — чтобы цвета были
  живыми и переключение тёмной/светлой темы работало без пересборки.
- **Без чужих библиотек компонентов.** Проект Make (React + shadcn/ui) — только
  визуальный эталон, его код не переносится. Пишем свои компоненты.
- **Связь с сервером через посредник разработки** (прокси на `/vitrine`,
  `/management`, `/operations` → `localhost:5025`). Серверный код не трогаем.
- **Единственная сетевая граница** «Angular ↔ Api». Фронт ходит только в адреса
  витрины и менеджмента, не знает о внутреннем устройстве сервера.

---

## 3. Принцип переноса дизайна

Дизайн переносим тремя отдельными слоями, не копируя чужой код:

1. **Тема (готова).** Цвета, типографика, тени, радиусы — в `theme_tokens_v1_0.scss`,
   объявлены один раз как переменные. В компонентах — только `var(--...)`,
   никаких вшитых `#6366F1`.
2. **Шрифты.** Те же, что в эталоне: Inter (интерфейс) и JetBrains Mono (числа,
   время, коды). Подключим в `index.html` или `styles.scss`.
3. **Разметка как образец.** Смотрим, как устроен экран Make, и пишем такой же на
   Angular, подставляя `var(--токен)` вместо вшитых цветов. Раскладку повторяем,
   код — нет.

**Что НЕ переносим:** файл темы Make (`theme.css` — чужая светлая заготовка,
не отражает реальных цветов экранов), компоненты React, библиотеку shadcn/ui.

---

## 4. Порядок срезов (один срез — один логический шаг)

Между срезами — проверка сборки и зелёный прогон, как на сервере.

| № | Срез | Адрес сервера | Чему учимся |
|---|---|---|---|
| 0 | Тема + шрифты в `styles.scss`, проверка | — | глобальные стили, переменные |
| 1 | Оболочка: боковое меню + рамка контента | — | селектор, RouterOutlet, вложение компонентов |
| 2 | Каталог (пустой экран по маршруту) | — | генерация компонента, маршрут, входной компонент в рамке |
| 3 | Каталог читает данные | `GET /vitrine/instruments` | служба HTTP, сигнал со списком, цикл `@for`, прокси |
| 4 | Каталог: вкладки, поиск, счётчики | — (фильтр на фронте) | вычисляемые сигналы, фильтрация |
| 5 | Карточка акции + блок «Связи» | `cards/stock`, `relations` | параметр маршрута, 404, второй запрос |
| 6 | Карточка фьючерса | `cards/futures`, `relations` | переиспользование, вычисление «до экспирации» |
| 7 | Форма связи (выдвижная панель) | `POST /management/relations` | форма, отправка, показ ошибки сервера |
| 8 | Издержки: список + форма тарифа | `GET/POST tariffs` | таблица, вторая форма, пустые поля «—» |
| 9 | Календарь | `GET /vitrine/calendar` | плашки статуса, фильтр рынка |
| 10 | Dashboard (сводка) | `GET /vitrine/status` | счётчики, плашки готовности |
| 11 | Кнопка первичной загрузки | `GET .../sync/bootstrap` | действие по кнопке, перечитывание |

После среза 11 — видение блока D (Загрузки, Качество, Рейтинг, Операции, Настройки),
когда заработает рыночная загрузка.

## 5. Обучающий маршрут (понятия по мере надобности)

Учим понятие ровно тогда, когда оно нужно срезу, а не впрок. Аналогии с .NET, где
уместно. Теория перед практикой, по одному понятию.

**Срез 0–1 (оболочка):**
- Глобальные стили и переменные темы (`:root`, `var(--...)`).
- Селектор как имя компонента; вложение компонентов через теги.
- `RouterOutlet` — рамка для сменных страниц по адресу.

**Срез 2–3 (каталог + данные):**
- Генерация компонента через CLI (`ng generate component`).
- Маршрут в таблице `app.routes.ts`: адрес → компонент.
- Сигнал как контейнер меняющегося значения (аналог наблюдаемого состояния).
- Служба HTTP (`HttpClient`) — обращение к серверу; провайдер в `app.config.ts`.
- Цикл `@for` в разметке (аналог `foreach`) — отрисовка списка.
- Посредник разработки (`proxy.conf.json`) — как фронт достукивается до сервера.

**Срез 4 (фильтры):**
- Вычисляемый сигнал (`computed`) — производное значение, считается само.
- Привязка значения поля к сигналу (двусторонняя связь ввода).

**Срез 5–7 (карточки и форма):**
- Параметр маршрута (`:secid`) — как адрес несёт данные.
- Обработка 404 и состояния «не найдено».
- Форма и её отправка; показ серверной ошибки (400 с текстом — дословно).

Дальше — добираем по ситуации: состояния загрузки/ошибки, выдвижная панель,
переходы.

## 6. Структура папок фронта (целевая, наполняем по мере роста)

Не заводим заранее — папка появляется, когда в неё кладём первый компонент.

```
frontend/src/
  styles.scss              # глобальные стили + импорт темы
  theme_tokens.scss        # переменные темы (из дизайн-системы)
  index.html               # подключение шрифтов
  app/
    app.ts / app.html / app.scss   # оболочка (меню + рамка)
    app.routes.ts                  # таблица маршрутов
    app.config.ts                  # провайдеры (HTTP и пр.)
    core/                          # службы доступа к серверу (HTTP)
    shared/                        # переиспользуемые мелкие компоненты
    features/                      # экраны по одной папке на раздел
      catalog/
      cards/
      calendar/
      costs/
      dashboard/
```

Соответствие именованию: один компонент — тройка файлов с общим именем
(`catalog.ts`, `catalog.html`, `catalog.scss`).

---

## 7. Дисциплина (как на сервере)

- **Тонкий сквозной срез:** один логический шаг — одна проверка сборки и зелёный
  прогон, потом коммит.
- **YAGNI:** компонент, папка, переменная появляются, когда нужны, не впрок.
  Колонку без источника не рисуем (см. карту экранов).
- **Цвет — через переменную, один раз.** Никаких вшитых значений в разметке.
- **Сервер не трогаем** на стороне фронта: всё общение через прокси и публичные
  адреса витрины/менеджмента.
- **Учимся на деле:** понятие вводится перед срезом, который его требует, и сразу
  применяется.

---

## 8. Ближайший шаг

Срез 0: положить тему и подключить шрифты в глобальные стили, прогнать `ng serve`,
убедиться, что фон стал тёмным по нашей палитре. Это первый видимый результат
переноса дизайна и проверка, что переменные темы работают.
