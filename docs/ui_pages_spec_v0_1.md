# Спецификация страниц пульта оператора

Версия 0.1. Документ описывает содержание каждой страницы: зачем она нужна, что на ней находится, какие действия и состояния у каждого экрана.

Визуальные правила, токены, компоненты и запреты описаны в отдельном документе «Правила интерфейса и дизайн-система оператора». Этот документ не повторяет их — он ссылается на дизайн-систему и описывает только содержание страниц.

---

## 1. Граница

Пульт — срез 5-A внутри фазы 5: минимальный пульт оператора. Автообновление в первой версии выполняется периодическими HTTP-запросами — это техническая гипотеза среза 5-A, а не постоянное UI-правило. Без авторизации, без ролей. Один оператор. Система может быть передана другому человеку: при первом запуске всё пусто, пульт ведёт нового пользователя от пустой системы до рабочего состояния через направляющие empty-состояния и информеры, без отдельного onboarding-экрана.

---

## 1.1. Общие правила страниц

Все страницы наследуют состояния из дизайн-системы: loading / empty / empty-filtered / populated / error. В этом документе описываются только отличия конкретной страницы: какой текст empty-состояния, какие действия доступны, какие таблицы и блоки показываются.

Визуальные правила, цвета, отступы, тени, поведение drawer/modal и статусные компоненты не повторяются здесь.

## 2. Карта страниц

| Route | Страница | Главный вопрос оператора |
|-------|----------|--------------------------|
| `/dashboard` | Dashboard | Что происходит с системой? |
| `/loads/jobs` | Загрузки — задания | Что я сейчас загружаю и что упало? |
| `/loads/ranges` | Загрузки — диапазоны | Какие данные уже есть в хранилище? |
| `/instruments` | Инструменты — список | Чем я управляю? |
| `/instruments/{secid}` | Инструменты — карточка | Что известно об этом инструменте? |
| `/calendar` | Календарь | Сегодня торговый день? Когда ближайшая экспирация? |
| `/quality` | Качество | Есть ли проблемы с загруженными данными? |
| `/costs` | Издержки | Сколько стоит торговля этим инструментом? |
| `/rating` | Рейтинг | Какой инструмент лучше всего подготовлен? |
| `/operations` | Операции | Когда последний раз синхронизировались справочники? |
| `/settings` | Настройки | Ключ APIM жив? Подключения работают? |

Навигация — sidebar с двумя секциями (МОНИТОРИНГ / АНАЛИТИКА). Настройки внизу, отделены разделителем. Карточка оператора в самом низу — локальная подпись пульта, не авторизация и не управление ролями.

Route по умолчанию: `/dashboard`. При пустой системе (instruments = 0) Dashboard открывается в setup-empty состоянии: показывает, что система ещё не наполнена, и предлагает первое действие.

## 3. Первый запуск

### Назначение

Первый запуск не выделяется в отдельную страницу. Пульт сразу открывает Dashboard, но показывает направляющие empty-состояния, информеры и подсказки рядом с теми местами, где оператор принимает решение.

### Принцип

Система не ведёт пользователя по линейному мастеру. Она показывает рабочий пульт сразу, но объясняет незаполненные места по месту.

### Что видит оператор при пустой системе

- Hero: состояние «Система не настроена». Главная кнопка: «Загрузить инструменты».
- Метрики: empty-значения с короткими пояснениями.
- Alerts: информер «Справочник инструментов не загружен».
- Последние загрузки: empty state с действием «Загрузить инструменты».
- Settings hint: «Ключ MOEX APIM понадобится для рыночных данных, но справочник можно загрузить без него».

### Информеры

Информер — короткая подсказка рядом с термином, статусом, полем или действием. Объясняет, что означает элемент и что будет после действия. Открывается по hover, click и focus на иконку «?» или «i».

Информеры используются рядом с: MOEX APIM, FUTOI, raw capture, rate limiter, «обогащено», «качество данных», «издержки», пустыми метриками.

Правило: информер объясняет, но не управляет. Критичные ошибки, блокеры и обязательные действия не прячутся во всплывающую подсказку.

### Последовательность настройки

Оператор проходит настройку через обычные страницы пульта:

1. Открыл Dashboard → увидел «Загрузить инструменты» → нажал → инструменты загружены.
2. Увидел в чеклисте «Ключ APIM не введён» → перешёл в Настройки → ввёл ключ.
3. Увидел «Календарь не загружен» → перешёл в Операции → нажал «Обновить всё» → управляющие справочники загружены.
4. Увидел «Заданий нет» → перешёл в Загрузки → создал первое задание.
5. Увидел «Тариф не введён» → перешёл в Издержки → добавил тариф.

Каждый шаг — обычная страница с обычным empty-состоянием. Не отдельный мастер.

## 4. Dashboard

### Назначение

Главный экран. Показывает состояние системы одним взглядом. Оператор проводит здесь 10–30 секунд.

### Главный вопрос

Что происходит с системой? Всё ли работает? Есть ли что-то, что требует моего внимания?

### Блоки (сверху вниз)

**Hero — статус системы.** Вариант определяется системным состоянием (источники, ключ, storage), а не ошибками отдельных заданий. Три строки-утверждения: инструменты под контролем, задания сегодня, качество данных. Чеклист: НАСТРОЕНО / НЕ НАСТРОЕНО в два столбца (инструменты, ключ APIM, календарь, карточки, тариф, автозагрузка).

**4 метрики.** Инструменты (число + breakdown акции/фьючерсы + delta). Задания сегодня (число + breakdown по статусам). Строк за 24 ч (число + средне/час + delta). Качество данных (процент + предупреждения/ошибки).

**КРИТИЧНО.** Alerts с severity = error. Секция скрыта, если ошибок нет. Пример: «GMKN candles 20.12—31.12 — задание упало».

**ВНИМАНИЕ.** Alerts с severity = warning и info. Экспирации, пропуски, ненастроенный тариф. Action-ссылки справа.

**Таблица последних загрузок.** 12 строк. Колонки: инструмент (тикер + тип данных), тип инструмента, период, строк, статус, время, действие, отслеживание. Caption со статус-breakdown и временем обновления.

**Footer.** Кнопка «Обновить справочники» (secondary). Primary action «Создать задание» — только в hero, не дублируется.

### Действия

- Создать задание → модалка создания.
- Открыть операции → navigate `/operations`.
- Клик на метрику → navigate на соответствующую страницу.
- Клик на alert action → retry / navigate.
- Клик на строку таблицы → переход на `/loads/jobs` с открытым DetailDrawer выбранного задания.

### Чего нет

Торговых графиков, свечей, стаканов. Inline-editing. Drag-and-drop.

## 5. Загрузки — задания

### Назначение

Рабочий экран управления загрузками. Создание заданий, мониторинг статусов, retry ошибок.

### Главный вопрос

Что я сейчас загружаю, что уже загружено, что упало, что требует действия?

### Блоки

**Page header.** Заголовок «Загрузки» + кнопки «Массовая загрузка» (secondary) и «Создать задание» (primary).

**Вкладки.** Задания / Диапазоны.

**StatusFilterChips (standalone).** Все · Ожидают · Выполняются · Успешно · Внимание · Ошибка. Каждый chip показывает count. Active-chip — через accent, статусный цвет — только для точки/счётчика внутри.

**FilterBar.** Инструмент (search-select), тип данных (multi-select: candles, tradestats, obstats, orderstats, futoi, hi2; mega_alerts — future), период (date-range), интервал (select, только если candles). Кнопка «Сбросить фильтры».

**Таблица заданий.** Колонки: ID (short 6 chars), инструмент (тикер + data_kind), интервал, период, строк (right-aligned mono), статус (badge), причина (truncated), время, действие (контекстное по статусу).

**Detail Drawer.** Slide-in справа по клику на строку. Параметры задания, результат, ошибка (если есть), действия (Повторить, Открыть инструмент).

### Действия

| Действие | Триггер | Компонент |
|----------|---------|-----------|
| Создать задание | Кнопка в header | Modal: autocomplete инструмент + тип + период + интервал |
| Массовая загрузка | Кнопка в header | Modal двухшаговый: выбор инструментов → матрица × типы данных |
| Повторить | Action в строке / drawer | Повторяет задание с теми же параметрами |
| Открыть детали | Клик на строку | Drawer slide-in |
| Фильтровать | Chips / FilterBar | Фильтрация таблицы |

### Правила создания задания

- Если data_kind ≠ candles → поле интервала скрыто.
- Если data_kind = futoi → подсказка: «FUTOI загружается по asset_code, не по secid. Для SiM6 будет использован Si.»
- Нерабочие дни в периоде → предупреждение (не блокер).
- Приостановки в периоде → предупреждение (не блокер).
- Период в будущем → ошибка (блокер).

### Правила массовой загрузки

Шаг 1: выбор инструментов (чекбоксы, поиск, фильтр по типу). Шаг 2: матрица инструменты × 6 типов данных, предзаполненная по типу инструмента (акция: все кроме futoi; фьючерс: все кроме orderstats). Общий период и интервал задаются один раз. Кнопка «Создать N заданий» показывает count до нажатия. Если часть заданий не проходит проверку — показать проблемные строки, остальные разрешить создать.

### Состояния

loading / empty («Заданий пока нет. Создайте первое задание.» + кнопка) / empty-filtered («Нет заданий по этим фильтрам.» + ссылка сбросить) / populated / error.

## 6. Загрузки — диапазоны

### Назначение

Обзор того, какие данные уже есть в хранилище. Вторая вкладка, менее приоритетна.

### Главный вопрос

Какие инструменты и типы данных покрыты? Где пробелы?

### Блоки

**4 summary-карточки.** Инструментов с загрузками, без загрузок, типов данных (6), строк всего.

**Таблица диапазонов.** Колонки: инструмент, тип данных, интервал, период, строк, хранилище, статус (ok/partial/stale), обновлено. Фильтры: устаревшие, partial, хранилище, secid.

**Подсказка FUTOI.** «FUTOI загружается по asset_code (Si), не по secid (SiM6).»

## 7. Инструменты — список

### Назначение

Список всех инструментов с фильтрацией, сортировкой и массовыми действиями.

### Главный вопрос

Чем я управляю? Какие инструменты обогащены, какие нет, за какими слежу?

### Блоки

**Вкладки.** Акции / Фьючерсы.

**Таблица акций.** Колонки: secid, shortname, list_level, lotsize, minstep, статус, обогащено (да/нет), связей (count), загрузок (count), уведомления (toggle), updated_at.

**Таблица фьючерсов.** Колонки: secid, asset_code, shortname, expiration_date, дней до экспирации, initial_margin, buysell_fee, обогащено, загрузок, уведомления (toggle). Группировка по asset_code.

**Фильтры.** Без обогащения, без связей, без загрузок, с изменёнными атрибутами, только с уведомлениями, поиск по secid/shortname, по asset_code.

### Действия

- Клик по строке → карточка инструмента.
- Toggle уведомлений — прямо в таблице.
- Чекбоксы → «Массовая загрузка» (двухшаговая форма).
- «Создать задание» для одного инструмента.

### Состояния

loading / empty («Справочник пуст. Загрузите инструменты с MOEX — бесплатно, 3 секунды.» + кнопка) / populated / error.

## 8. Инструменты — карточка

### Назначение

Всё об одном инструменте: параметры, связи, загрузки, дыры, приостановки, качество, издержки.

### Route

`/instruments/{secid}`

### Шапка

Тикер, shortname, тип инструмента, статус торгов, updated_at. Для фьючерса: дней до экспирации (цветовая индикация). Toggle «Отслеживать».

### Секции

| Секция | Содержание |
|--------|-----------|
| Параметры | Все атрибуты из Securities/MarketStatistics. Nullable поля с пометкой «не обогащено» |
| Связи | source → target, relation_type, confidence. Кнопка «Добавить связь» |
| Загруженные диапазоны | data_kind, interval, период, строк, хранилище, статус (ok/partial/stale) |
| Дыры | Временная шкала: закрашенные полосы = загружено, пустые = дыры. Пропущенные даты текстом |
| Приостановки | Таблица: date_from, date_till, reason (расшифровка), boardid. Активные выделены |
| Изменения атрибутов | moex_update_time, action, attribute_name, before_value, after_value |
| Издержки | Биржевая + брокерская = полная. Round-trip = 2 × полная |
| Качество | check_type, status, result, check_date, details |

### Действия

«Создать задание» (предзаполненный secid). «Обогатить MarketStatistics». «Проверить качество».

## 9. Календарь

### Назначение

Торговые дни, сессии, экспирации. Ответ на вопрос: «сегодня работаем?»

### Главный вопрос

Сегодня торговый день? Когда следующий нерабочий? Когда ближайшие экспирации?

### Блоки

**Сегодня.** Два столбца: фондовый + срочный рынок. Торговый/нерабочий. Расписание сессий (тип, время). Следующий клиринг.

**Календарная сетка.** Месячный вид. Ячейки: торговый (нейтральный), праздник (красный), торговый выходной (оранжевый), обычный выходной (серый). Счётчик торговых дней.

**Экспирации.** Таблица: secid, asset_code, expiration_date, дней, expiration_type. Контракты < 30 дней.

## 10. Качество

### Назначение

Проверки данных после загрузки. Расхождения, дыры, проблемы.

### Главный вопрос

Есть ли проблемы с загруженными данными? Что нужно перепроверить?

### Блоки

**3 summary-карточки.** Проверок сегодня (ok/warning/error), непроверенных диапазонов, с проблемами.

**Таблица проверок.** secid, data_kind, check_type, status (pending/running/checked/error), result (ok/warning/error), check_date, details (expand).

**Расхождения экспираций.** secid, Calendar expiration_date, ISS last_trade_date, разница.

### Действия

«Запустить проверку» (для одного), «Проверить все».

### Состояния

loading / empty («Проверки запускаются автоматически после загрузки данных.») / populated / error.

---

## 11. Издержки

### Назначение

Тарифы брокера и калькулятор полных издержек.

### Блоки

**Текущие тарифы.** broker_name, tariff_name, market, fee_type, fee_value, fee_currency, valid_from.

**Калькулятор.** Выбор инструмента → биржевая + брокерская = полная. Round-trip. Сравнение нескольких.

**История тарифов.** Все тарифы, включая закрытые.

### Действия

«Добавить тариф», «Закрыть тариф».

### Состояния

empty («Тарифы брокера не введены. Это не блокирует загрузку.» + кнопка «Добавить тариф») / populated.

---

## 12. Рейтинг

### Назначение

Сводная оценка готовности каждого инструмента к торговле.

### Главный вопрос

Какой инструмент лучше всего подготовлен? По какому критерию выбрать?

### Таблица

secid, instrument_type, asset_code, rows_total, data_kinds_covered, full_commission, liquidity, quality_ok, composite_score. Сортировка по любому столбцу.

### Фильтры

Тип инструмента, только с загрузками, только с качеством ok, минимальный rows_total.

### Состояния

empty («Для рейтинга нужны загруженные данные, проверки и тарифы. Экран заработает, когда система наполнится.» + ссылка «Перейти к загрузкам») / populated.

---

## 13. Операции

### Назначение

Синхронизация справочных данных с MOEX. Центр управления периодическими обновлениями.

### Главный вопрос

Когда последний раз обновлялись справочники? Есть ли ошибки синхронизации?

### Блоки

**Таблица синхронизаций.** Для каждого типа данных: тип, нужен ли ключ, последняя синхронизация, записей, ошибка, кнопка «Обновить». Кнопка «Обновить всё».

**Автоматические задания.** Включить/выключить ежевечернюю загрузку свечей. Список инструментов, время запуска, лог последних запусков.

---

## 14. Настройки и система

### Назначение

Ключ APIM, подключения, raw capture, rate limiter, наблюдаемость.

### Секции

**Ключ MOEX APIM.** Статус (введён/не введён), маскированный ключ, кнопки «Проверить» и «Изменить», ссылка на получение.

**Raw capture.** Режим (Off/FailedOnly/Sample/All), переключатель, записей за сутки, ошибок.

**Rate limiter.** Текущий лимит (req/s), утилизация, среднее ожидание, P95 ожидание.

**Подключения.** Таблица: сервис (PostgreSQL, объектное хранилище S3, ClickHouse, MOEX ISS, MOEX APIM), URL, статус, задержка.

**Наблюдаемость.** Ссылки на Grafana-дашборды.

## 15. Пустые состояния (сводка)

Каждая страница при отсутствии данных показывает направляющее сообщение с кнопкой, а не пустую таблицу.

| Страница | Текст | Кнопка |
|----------|-------|--------|
| Инструменты | Справочник пуст. Загрузите инструменты с MOEX — бесплатно, 3 секунды. | Загрузить инструменты |
| Календарь (нет ключа) | Календарь не загружен. Нужен ключ MOEX APIM. | Перейти в настройки |
| Календарь (ключ есть) | Календарь не загружен. | Загрузить календарь |
| Загрузки — задания | Заданий пока нет. Выберите инструмент и создайте первое задание. | Создать задание |
| Загрузки — диапазоны | Загруженных диапазонов нет. | Создать задание |
| Качество | Проверки запускаются автоматически после загрузки данных. | — |
